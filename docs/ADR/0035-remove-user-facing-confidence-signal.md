# ADR 0035: Remove the User-Facing Confidence Signal

Date: 2026-06-07

## Status

Accepted. **Supersedes items 5, 6, and 8 of [ADR 0026](0026-polish-output-naturalness.md)**
(inline-score → confidence-cue rendering, confidence-based folder ordering, and the
TUI confidence label). The rest of ADR 0026 (the `_Review` → `Outros` rename,
`display_name`, the merged-"Outros" bucket, the Unicode glyphs and summary preamble)
stands unchanged.

## Context

ADR 0026 surfaced the per-folder silhouette score to users as a three-level
confidence cue — colour bands (green / yellow / red), a `· verificar` label on
low-confidence folders, folder ordering by confidence, and a `--scores` flag to
reveal the raw number. The signal rode on the product contract:
`FolderNode.cohesion` and `StructureProposal.cohesion_score` (contract v3).

There is **no validated claim** that a per-folder silhouette value reliably
predicts whether a user will accept or reject that folder. Surfacing it as a
"confidence" cue implies a reliability the project has not demonstrated. The
silhouette work belongs to the *empirical characterization* (thesis Ch4), where
it is a structure-finding instrument measured against a random baseline — not a
product feature with a user-facing accuracy promise.

Keeping the signal in the product also keeps a claim in the thesis that the tool
would have to defend. Removing it now lets Ch4 make the honest, narrower claim:
*we measure cohesion to characterize the system; we deliberately do not present
it to users.*

## Decision

1. **Remove the confidence signal from the product contract.** Delete
   `FolderNode.cohesion` and `StructureProposal.cohesion_score`. Bump
   `StructureProposal.contracts_version` **3 → 4** (a genuine breaking change —
   fields removed). Update `docs/CONTRACTS.md`.

2. **Strip the render surface.** Remove `confidence_band`, `color_for_band`, the
   `· verificar` label, the colour wrapping, the `--scores` CLI flag, and the
   `show_scores` plumbing (CLI → `launch_tui` → `webview_app` → `render_tree`).
   Folder lines now show only the name and direct-file count.

3. **Replace the sort key.** Top-level and nested folders sort by
   **direct-file-count DESC, then name ASC** — deterministic and independent of
   any quality signal. The "Outros" bucket still renders last.

4. **Stop computing cohesion in the proposer.** The proposer no longer imports
   `calculate_silhouette_score` / `calculate_per_cluster_silhouette` and no
   longer emits the `"Cohesion Score (Silhouette)"` note.

5. **Keep `clustering/metrics.py`.** The silhouette math stays for the
   evaluation-only path. Chapter 4's numbers are regenerated by standalone
   characterization tooling that imports `metrics.py` directly, **not** from the
   product contract.

6. **Drop the benchmark's quality grading.** `core/benchmark.py` no longer reads
   `cohesion_score`; the grid records structural facts (cluster count, outliers,
   duration) only, and the cohesion-sorted leaderboard is removed.

## Rationale

- **Honesty over surface area.** Aligns with the project's "simple, solid,
  robust" direction and the thesis's honesty bar: ship only claims the system
  can defend.
- **Right home for the metric.** Silhouette is an evaluation instrument. Moving
  it entirely off the product contract draws a clean line between *what the tool
  does* (propose folders) and *how we characterize it* (Ch4).
- **Deterministic ordering without a quality proxy.** File-count ordering keeps
  the strongest-looking groups near the top without implying a measured
  confidence.

## Consequences

- **Breaking contract change (v4).** Consumers of `cohesion` / `cohesion_score`
  must drop those fields. No other contract is affected.
- **Tests updated.** `test_render_polish.py` (sort + "fields gone" assertions),
  `test_sprint9_triage.py` (plain render), `test_sprint8_clustering_research.py`
  (obsolete score test removed), `test_sprint10_benchmark.py` (structural keys),
  `test_reducer.py` (scan-note proxy), and the `contracts_version` assertions in
  `test_cli_smoke.py`, `test_extractor_and_preprocess.py`,
  `test_sprint17_recursive_hierarchy.py`. Full suite green (216 passed, 3
  skipped).
- **Thesis ripple (tracked separately).** Ch3 and Appendix §I.III describe the
  confidence bands as a shipped feature; those become evaluation-only framing.
  See the thesis gap register (GAP B).
- **Phase β unaffected.** The namer/clusterer failure modes from ADR 0026 remain
  scoped as before.

## Alternatives considered

- **Keep computing cohesion internally on `RunResult` as a non-serialized
  diagnostic.** Lighter, keeps Ch4 trivially reproducible from a pipeline run.
  Rejected in favour of a clean break: the characterization tooling computes
  silhouette itself, so no quality signal lingers anywhere in the product path.
- **Keep the field, stop rendering it.** Avoids a contract bump but leaves a
  dead "confidence" field on the contract inviting re-surfacing. Rejected.
